## 의사결정 배경 정리

### 엑심베이

**Turborepo 모노레포 선택**

- 배경: 멀티 앱(백오피스, 어드민) 구조에서 공통 코드 중복 발생 예상
- 결정: Turborepo + pnpm workspace로 공유 패키지 분리
- 결과: 공통 UI 변경 시 PR/리뷰/배포 2회 → 1회로 통합

**ESLint 의존성 규칙 자동 강제**

- 배경: 아키텍처 규칙을 문서로만 전파하면 시간이 지나며 위반 누적
- 결정: import-x/no-restricted-paths로 레이어 간 방향을 빌드에서 차단
- 결과: 순환 참조 0건, 아키텍처 무결성 유지

**MSW 기반 독립 Mock 환경**

- 배경: 백엔드 API 개발 일정이 프론트 일정보다 느림
- 결정: MSW로 네트워크 레벨 모킹, 백엔드 의존 없는 개발 환경
- 결과: 백엔드 완성 전부터 피처 개발 및 모바일 QA 병행 가능

**MPC 서명 동시성 제어**

- 배경: 동일 지갑에 동시 서명 요청 시 MPC 프로토콜이 거부
- 결정: 지갑 단위 비동기 큐(Promise 체인)로 순차 처리
- 결과: 서명 거부 에러 예방, 다른 지갑은 병렬 처리 유지

### 파이노버스랩

**JSON Server → MSW 전환**

- 배경: JSON Server는 localhost 바인딩이라 모바일 실기기 테스트 불가, 배포 환경에서 Mock 미동작
- 결정: 비교 분석 문서 작성 후 팀 제안 → MSW(Service Worker 기반) 전환
- 결과: 모바일/배포 환경 QA 가능, 백엔드 의존 없는 병렬 개발로 스프린트 2~3주 단축

**Playwright E2E + CI/CD 연계**

- 배경: 결제 서비스 변경 시 수동 회귀 테스트에 2~3일 소요
- 결정: 핵심 결제 플로우를 Playwright E2E로 자동화, CI/CD에 연계
- 결과: QA 기간 2~3일 → 반나절, 결함 코드 배포 원천 차단

**서버리스 API 단독 개발**

- 배경: 백엔드 리소스 부족으로 가입 플로우 블로킹, 출시 지연 위기
- 결정: FE 개발자로서 직무 경계를 넘어 AWS Lambda 기반 API를 직접 설계·배포
- 결과: 가입 병목 해소, 장애 0건 운영

**LocalStack 로컬 검증 환경**

- 배경: Lambda 코드 수정마다 AWS 배포 필요 → 긴 피드백 루프
- 결정: LocalStack + Docker로 Lambda/API Gateway를 로컬에 재현
- 결과: 배포 없이 통합 검증 가능, 개발 속도 향상

**정산 어드민 리뉴얼**

- 배경: 레거시 어드민에서 수수료 검증을 수동으로 1시간/건 소요
- 결정: Next.js 리뉴얼 + 달력 UI 기반 자동 계산 도입 + 유닛 테스트
- 결과: 건당 1시간 → 즉시 확인, 정산 오류 사전 차단

**S3 이메일 템플릿 버전 관리**

- 배경: 이메일 배포 후 S3에서 직접 텍스트 대조 확인 필요 (10분/건)
- 결정: 버전 관리 체계 제안 및 자동 버저닝 스크립트 구축
- 결과: 배포 확인 10분 → 1분 (버전 번호만 확인)

### 제머나이소프트

**Canvas + DOM 하이브리드 렌더링**

- 배경: DOM만으로 타임라인 렌더링 시 아이템 증가에 따른 프레임 드랍
- 결정: 정적 요소는 Canvas, 인터랙티브 요소는 DOM으로 분리
- 결과: 프레임 드랍 상당 수준 해결

**모니터링 메모리 누수 해결**

- 배경: 24시간 가동 대시보드가 약 16시간 후 OOM으로 다운
- 결정: 힙 스냅샷 시간차 비교 분석 → setInterval 미해제 특정
- 결과: 72시간+ 무중단 가동 확인

**Node.js 빌드 버전 표준화**

- 배경: 배포 서버 간 Node.js 버전 불일치로 빌드 오동작, 프로젝트 3개월 지연
- 결정: 빌드 환경 버전 표준화
- 결과: 문제 해결 후 2주 조기 배포

### 개인 프로젝트 (potato)

**Repository 패턴 도입**

- 배경: Supabase 네트워크 장애 시 빌드/개발 자체가 불가
- 결정: Repository 인터페이스 추상화로 외부 의존 격리
- 결과: DB 없이도 정상 빌드/구동되는 독립 개발 환경

**SEO 최적화**

- 배경: 실제 업체 홈페이지라 검색 노출이 비즈니스에 직결
- 결정: On-demand ISR, JSON-LD, 동적 Sitemap, Gemini API 메타데이터 자동 생성
- 결과: Lighthouse SEO 100점, Performance 98점, 네이버 키워드 최상위, 구글 첫 페이지 상위

## 사용하지 않는 것 (수치화 어려움 또는 임팩트 약함)

- LocalStack: "단축" 수치보다 "검증 수단 추가" 성격
- HMR: 체감은 있으나 수치화 어려움
- 슬랙 워크플로우: 단순 반복 제거
- MVP 출시 기간: 기억 안 남
- 컴포넌트 수, 코드 라인 수: 임팩트 없음
