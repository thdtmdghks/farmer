# 기술 결정 기록

## 001: 싱글 페이지 스크롤

라우터 없이 스크롤만으로 완결.

- 채용 담당자는 30초 안에 판단함. 클릭 → 이동은 이탈 위험
- 스크롤은 모바일에서 가장 자연스러운 인터랙션
- TanStack Router 제거로 번들 경량화

감수하는 단점: 프로젝트별 깊은 상세(코드 예시, 다이어그램)는 넣기 어려움.
전환 시점: Decision이 10개 이상으로 늘어나 스크롤 피로가 생기면 라우터 재도입.

## 002: 모바일 퍼스트

기본 스타일이 모바일, `sm:`/`md:`로 확장.

- Tailwind 기본 설계와 일치
- 좁은 화면에서 먼저 잘 보이면 넓은 화면은 여백만 추가하면 됨
- 모바일에서 확인할 가능성도 있으므로 대응 필수

감수하는 단점: 데스크톱에서 `max-w-3xl`로 좌우 여백 넓음. Decision 카드가 모바일(세로 스택)과 데스크톱(가로 배치) 두 레이아웃 모두 신경 써야 함.

## 003: 네이티브 API 우선 (외부 애니메이션 라이브러리 없음)

IntersectionObserver + CSS transition으로 충분.

- 필요한 애니메이션이 fade/zoom 4종뿐. Framer Motion(+30KB)은 과도
- GPU 가속 CSS transition으로 성능 우수
- 기존 `useInView` + `AnimateOnScroll` 재활용

감수하는 단점: 스프링 물리, 제스처, 레이아웃 애니메이션 등 복잡한 효과는 구현 비용 높음.
전환 시점: 복잡한 인터랙션이 필요해지면 해당 컴포넌트에만 Framer Motion 부분 도입.

## 004: 데이터 파일 분리

`data/resume.ts` 한 파일에 모든 콘텐츠.

- 수정 시 이 파일만 열면 됨
- TypeScript 타입 체크로 구조 오류 즉시 감지
- CMS는 1인 프로젝트에 과도

감수하는 단점: 콘텐츠 수정 시 코드 에디터 필요.
전환 시점: 데이터가 길어지면 `data/experiences.ts`, `data/decisions.ts`로 분할.

## 005: 모노톤 색상

shadcn Neutral 팔레트. 브랜드 컬러 없음.

- 주인공은 콘텐츠이지 디자인이 아님
- 다크모드 전환이 CSS 변수 반전만으로 완결
- 채택/기각 구분은 테두리 굵기 + 텍스트 라벨로 (색상 의존 안 함 → 색맹 대응)

감수하는 단점: 시각적 임팩트가 약할 수 있음.

## 006: @media print PDF 대응

별도 PDF 관리 대신 브라우저 인쇄로 PDF 생성.

- 웹과 PDF가 항상 동기화 (단일 소스)
- 추가 의존성 없음

감수하는 단점: 브라우저별 인쇄 렌더링 차이, 페이지 브레이크 제어 불완전.
전환 시점: 정교한 PDF 레이아웃이 필요해지면 별도 PDF 파일 추가.

## 007: GitHub Pages 배포

Vercel 대신 GitHub Pages.

- 싱글 페이지 정적 사이트라 SPA 라우팅 제한 해당 없음
- GitHub 하나로 소스 + 배포 관리
- GitHub Actions로 push 시 자동 배포

감수하는 단점: Edge CDN 성능 Vercel보다 약간 떨어짐 (체감 미미). PR별 프리뷰 배포 없음 (1인 프로젝트라 불필요).
